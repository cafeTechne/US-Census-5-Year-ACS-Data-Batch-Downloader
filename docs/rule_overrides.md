# Table-scoped rule overrides

Some releases restructure a whole table at once. In the 2017 subject-table redesign, for example, S1701 (poverty status) inserted the universe header "Population for whom poverty status is determined" into every line of its main block:

```
2016 S1701_C01_002  total!!age!!under 18 years
2017 S1701_C01_002  total!!population for whom poverty status is determined!!age!!under 18 years
```

Exact-label matching cannot link these lines, so each one shows up as a `relabeled` or `redefined` issue (171 of 183 lines in S1701 at 2016 -> 2017). Reviewing them one row at a time is impractical. A **rule** records one reviewed regular-expression rewrite that covers all of them.

## What a rule is

- A rule belongs to one table and one adjacent vintage boundary (`from_year` -> `to_year`, where `to_year` is the next published vintage). It never spans tables or boundaries.
- It rewrites the **canonical labels** (`census.concordance.canonical_label`) of the earlier vintage with `re.sub(pattern, replacement, label)`. Rewritten parts are trimmed, whitespace-collapsed, and lowercased, and empty parts are dropped.
- When a rewritten earlier line's match key (the order-insensitive set of label parts) equals the key of exactly one later line, the two concepts are linked into one. The later concept keeps its ID, and the earlier concept's codes (including the years before `from_year`) move into it.
- Rules only add merges. Merged concepts get the `overridden` status, so the national continuity check runs on them at extraction like any other merge. A missing national value blocks (`continuity_unavailable`), and a rule never grants a continuity exception.
- Rules do not compose. Each rule sees the original canonical labels, and two rules on the same boundary may not claim the same earlier or later line.
- A rule applies only when both years of its boundary are in the requested range. A request for 2015 and 2017 without 2016 is not affected by a 2016 -> 2017 rule.

Rules live in `crosswalks/<dataset>/<TABLE>_rules.csv`:

```
table,from_year,to_year,pattern,replacement,rationale,source_url,evidence_id,drafted_by,reviewed_by,reviewed_on
```

`build_concordance` applies valid rules automatically. Invalid rows are never applied; each one becomes a blocking `invalid_override` issue.

## Evidence

Evidence is generated by `census.concordance.build_rule_evidence` from archived metadata only, and saved as `crosswalks/evidence/<evidence_id>.json`. The ID is the hash of the content, in the same style as single-line overrides. The evidence contains:

- `rewrites`: every `(code, before, after)` label rewrite;
- `matches`: each new link (`from_code` -> `to_code`, with the later label);
- `unmatched`: rewritten lines that match nothing, with a reason;
- `conflicts` and `numeric_changes`: guardrail violations (must be empty);
- the pattern, replacement, boundary, metadata source per year, and normalization version.

Validation regenerates the evidence from the row and the archive and requires an exact match. Hand-edited evidence, evidence for a different pattern, and evidence that went stale after an archive refresh are all rejected.

## Guardrails (enforced at validation)

A rule is rejected if:

1. it rewrites zero labels, or produces no new matches;
2. it changes any number in any rewritten label (the sorted multiset of numbers before and after must be equal). This covers age, dollar, percent, and other bounds. For example, the S1601 2017 header "Population 5 years and over" cannot be added by a rule; those lines need single-line review;
3. it maps two earlier codes to one later line, links an earlier line that already continues automatically to a different later line, or links a later line that already has an exact earlier match;
4. the boundary is not one adjacent vintage step;
5. `source_url` is not on `census.gov`, identities are malformed, or `reviewed_by` equals `drafted_by`;
6. the evidence is missing, does not hash to its ID, or does not match the regenerated evidence.

## Workflow for agents

### Drafter

1. Run `check_variable_concordance` on the table and boundary. Look for many `relabeled`/`redefined` issues that differ by the same header part.
2. Confirm in a Census primary source (table and geography changes for the release, or the table shells) that the change is a restructuring of labels and not a change in what is measured.
3. Write the narrowest pattern that covers the affected block. Anchor it (`^...`) and list the sub-headers explicitly instead of using `.*`.
4. Call `draft_rule_override(table, dataset, from_year, to_year, pattern, replacement, drafted_by, rationale, source_url)`. Read the `preview` (`labels_rewritten`, `new_matches`, `still_unmatched`) and `guardrail_errors`. Evidence is saved only when the guardrails pass. With a client, `continuity` previews the national check for every new match. Treat any flagged match as a sign that the rule is wrong.
5. Hand the draft row and evidence ID to a different reviewer.

### Reviewer (different identity)

1. Open `crosswalks/evidence/<evidence_id>.json` and read every rewrite and match, not a sample. Check that each match pairs the same measure (usually the same line number in a redesign).
2. Open the cited `source_url`.
3. If you agree, call `record_rule_review(row, reviewed_by=<your identity>, dataset=...)`. The row is validated and appended to `<TABLE>_rules.csv`. If you disagree, do not record it.

`validate_all_crosswalks` (CLI `python -m census validate-crosswalks`) validates rule files with the same checks, including conflicts between rules.

## Python API

```python
from census.review import draft_rule_override, record_rule_review

draft = draft_rule_override(
    "S1701", "subject", 2016, 2017,
    pattern=r"^(total|below poverty level|percent below poverty level)!!(age|sex|race and hispanic or latino origin|educational attainment|employment status|work experience|all individuals with income below the following poverty ratios)(!!|$)",
    replacement=r"\1!!population for whom poverty status is determined!!\2\3",
    drafted_by="agent:claude-opus-5-5/session-a",
    rationale="2017 redesign inserted the universe header; line content unchanged.",
    source_url="https://www.census.gov/programs-surveys/acs/technical-documentation/table-and-geography-changes/2017/5-year.html",
)
# draft["preview"] -> 126 labels rewritten, 126 new matches, 0 still unmatched
record_rule_review(draft["draft_row"], "agent:claude-opus-5-5/session-b", "subject")
```
