# Pre-registered analysis

Goal: a confirmatory analysis fixed before the data are pulled.

1. Write the manifest (JSON or YAML): research question, table, variables (codes or `YEAR:CODE`), geography, releases, derivations, tests or model formula, multiple-comparison correction, and reliability exclusions.
   - Several states: `"geography": {"level": "county", "states": ["26", "36"]}` (instead of `"state"`; no `codes`; exactly 2-digit FIPS strings, `"06"` not `"6"`; not for `zcta`, whose GEOIDs are not state-prefixed). States are stacked; add a state term to the formula yourself, e.g. `C(GEOID.str[:2])`.
   - Price adjustment: `"adjustments": [{"type": "rpp", "variables": ["income"], "rpp_year": 2024}]` divides dollar variables (and their SEs and replicates) by the BEA Regional Price Parity of each county's metro area or the state's nonmetro portion. `rpp_year` is required so the hash fixes it; when it is omitted, `create_manifest` fills in the latest RPP year, says so in its result, and writes the completed manifest to a new `<name>.completed.json` (the input file is never overwritten); commit and run that file. Exclusions run before the adjustment, so a pre-registered `geoid_exclude` can drop a unit without an RPP area; any remaining unit without one blocks the run (`adjustment_failed`). Not combinable with `aggregation`.
   - Several releases (non-overlapping 5-year periods, e.g. `"releases": [2019, 2024]`): the adjustment also needs `"dollar_year": 2024`, `"price_index": "r-cpi-u-rs"` and `"rpp_years": {"2019": 2019, "2024": 2024}` (instead of `rpp_year`). Each release's dollars are converted to the dollar year with the price index first, then divided by the RPP of that release's own year; the methods text states the order. `create_manifest` fills omitted fields (latest release, R-CPI-U-RS, each release's own year) into `<name>.completed.json`, as above. Contrast the releases with `C(Year)` in a formula, e.g. `"income ~ C(Year)"`.
   - Census replicates: `"replicates": {"source": "census_vre"}` makes `run_manifest` fetch the Census VRE files for the manifest's tables, geography and releases (cached under `.cache/vre`); `run.json` records each file's URL and SHA-256. Do not pass `replicates_path` as well (an error). Tract and block-group VRE files are per state, so give `geography.state` or `states`. Releases must not overlap for any replicate source: validation refuses `census_vre` or an analysis declaring `"replicates": "required"` with overlapping 5-year periods, and caller-supplied replicates (`replicates_path`) spanning overlapping releases stop every replicate analysis (`replicates_overlapping_releases`, blocking). Variables without published replicates (e.g. `B19013`) are listed by `create_manifest` and in `run.json` (`replicates.unavailable`); a replicate analysis that uses them stops (`replicates_incomplete`) unless that analysis declares `"replicate_scope": "covariates_only"` (`fit_replicate` only; the outcome is held at its estimate in every refit; target `population` or `conservative`). The declaration is also allowed for an outcome the VRE registry lists (its line can still be missing for your units): `create_manifest` notes it, and if the run finds replicates for the outcome it still holds it fixed as declared and records `replicates.covariates_only_outcome_had_replicates`.
2. Validate it with `create_manifest` (full profile); it checks every variable resolves and records the manifest's SHA-256. Commit the manifest to the repository before running.
3. Run it with `run_manifest` and the manifest path. It runs `plan_extraction`, the download, derivations and models exactly as written.
4. Do not change the manifest after seeing results. Anything you run outside it on the same data is exploratory; label it so.
5. Report the manifest hash with every result, plus estimates with 90% MOEs or model SEs with their uncertainty sources.
